# 벤치마크 관찰성 및 재개 가능한 제어 설계

## 목표

벤치마크 실행에서 모델별 실제 입력, 응답, 점수, 실패 원인을 항목 단위로 확인하고, 일시정지와 중지 이후 완료된 작업을 보존한 채 남은 작업부터 안정적으로 재개한다. 현재 `SCORING`에 정체된 실행도 성공 응답 60건을 보존하고 EXAONE 실패 30건만 재실행할 수 있어야 한다.

## 확인된 장애 원인

1. EXAONE의 `EXAONE_BASE_URL=https://api.friendli.ai`에 공통 어댑터가 `/chat/completions`를 붙여 존재하지 않는 경로를 호출했다. Friendli Model API의 OpenAI 호환 Base URL은 `https://api.friendli.ai/serverless/v1`이다.
2. Gemini 채점 응답의 `evidence`가 문자열 배열로 반환됐지만 채점 스키마는 객체 배열만 허용했다. Zod 파싱 오류가 워커 최상위 루프까지 전파되어 실행이 `SCORING` 상태에 고정됐다.
3. `RETRY_FAILED`는 실패 항목만 `PENDING`으로 바꾸고 `SCORING` 실행을 `RUNNING`으로 되돌리지 않아 실제 재실행이 불가능했다.
4. 실행 상세 화면은 집계와 이벤트 이름만 표시해 실제 입력·응답·점수·오류 내용을 관찰할 수 없었다.

## 상태 및 제어

- `PAUSING`: 새 항목 할당을 중지하고 이미 외부 API에 전달된 요청은 완료시킨다. 임대 항목이 모두 정리되면 `PAUSED`가 된다.
- `STOPPING`: 새 항목 할당을 중지하고 진행 중 요청에 중단 신호를 전달한다. 중단된 항목은 시도 횟수를 소모하지 않고 `PENDING`으로 복원한다. 임대 항목이 사라지면 `STOPPED`가 된다.
- `RESUME`: `PAUSED` 또는 `STOPPED`에서 `RUNNING`으로 전환한다. `SUCCEEDED` 항목은 다시 실행하지 않는다.
- `CANCEL`: 영구 종료 용도로 유지한다. 화면에서는 “영구 취소”로 명확히 표시한다.
- 채점 중 실패 항목 재시도는 실패 수를 재계산하고 실행을 `RUNNING`으로 되돌린다. 이미 저장된 응답과 점수는 멱등적으로 재사용한다.

상태 전이는 DB 트랜잭션과 행 잠금으로 직렬화한다. 워커는 실행 상태를 주기적으로 확인해 중지 신호를 AbortController에 전달한다. 일시정지는 진행 중 응답 저장을 허용하고, 중지는 해당 응답을 저장하지 않은 채 항목을 다시 대기 상태로 돌린다.

## 실행 관찰성

각 `run_item`의 최신 요청 스냅샷을 외부 호출 전에 저장한다. 스냅샷에는 시스템 프롬프트, 사용자 프롬프트, 근거, 질문, 선택지, 모델과 시도 번호가 포함된다. 성공 여부와 무관하게 같은 상세 API에서 다음을 반환한다.

- 문항 ID·질문·정답 형식·교과서 근거
- 실제 시스템 프롬프트와 사용자 프롬프트
- 모델 응답, 원본 응답, 요청 ID, 토큰, 지연 시간
- 지표별 점수, 라벨, 판정 근거, 인용 근거
- 실행 상태, 실패 코드·메시지, 재시도 기록

실행 상세 화면은 모델·상태 필터와 항목별 펼침/닫힘 목록을 제공한다. SSE 이벤트는 진행률과 상태를 즉시 갱신하고, 항목 내용은 상세 API를 재조회한다. 채점 오류도 `RUN_SCORING_FAILED` 이벤트로 노출한다.

## 평가 프로필 공개

실행 상세 화면과 시스템 설정에서 평가 프로필의 버전, 제목, 지표 목록, 지표별 한국어 설명, 루브릭 프롬프트, 심사 제공자·모델, 내용 해시를 표시한다. 선수관계 문항에 동적으로 추가되는 지표도 별도 목록으로 보여준다.

## 장애 복구

채점 `evidence`는 문자열을 `{ claim: 문자열 }`로 정규화하고 객체는 허용된 필드만 보존한다. 구조가 완전히 잘못된 채점 응답은 실행 전체를 무한 반복시키지 않고 오류 이벤트와 마지막 오류를 저장한다. 수정 배포 후 현재 실행의 EXAONE 실패 항목을 대기 상태로 되돌려 올바른 Friendli 경로로 재실행하고, 기존 Gemini·Upstage 응답 60건은 유지한다.

## 테스트

- 상태 전이 단위 테스트: 일시정지, 중지, 재개, 영구 취소
- 통합 테스트: 임대 항목 drain, 중지 시 pending 복원, `SCORING` 실패 재시도
- 채점 단위 테스트: 문자열/객체 evidence 정규화
- 실행 상세 페이지 테스트: 입력·응답·점수·실패 및 프로필 표시
- 전체 단위·통합 테스트, Next.js 빌드, Docker 재배포 후 현재 실행 복구 검증

## 범위 제한

별도 메시지 브로커나 새로운 외부 서비스는 도입하지 않는다. 기존 PostgreSQL 큐, SSE, 워커 구조를 확장하며 기존 성공 응답과 점수는 삭제하지 않는다.
