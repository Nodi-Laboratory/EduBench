# Research Audit Workspace Design

## 목적

EduBench를 단순 결과 표시 도구가 아니라 연구자가 데이터셋 구성, 문항 설계 의도, 교과서 근거, 선수관계 추론 구조, 채점 정의를 역추적할 수 있는 벤치마크 감사 도구로 확장한다.

## 범위

- 데이터셋 화면에서 현재 승인 작업 세트와 발행된 불변 데이터셋 버전을 모두 조회한다.
- 발행 버전은 `dataset_questions.question_revision`에 고정된 문항 내용을 보여 주며 현재 revision과 혼합하지 않는다.
- 채점 프로필 화면에서 각 지표의 정의, 판정 방식, 점수 해석, 루브릭과 Judge 구성을 공개한다.
- 실행 중 생성된 요청·응답·점수·판정 근거는 기존 실행 상세 화면으로 연결하고, 데이터셋/프로필 화면은 그 전 단계의 설계와 재현 정보를 담당한다.

## 데이터셋 감사 화면

### 작업 세트

현재 `APPROVED` 상태인 실제 생성 문항을 표시한다. 검색과 목적, 난이도, 형식, 근거 모드 필터를 제공하며 각 문항에서 다음을 펼쳐 볼 수 있다.

- 공개 ID, 현재 revision, 상태, 과목, 학년, 단원
- 질문 목적, 난이도, 문항 형식, 근거 모드
- 질문 원문, 선택지, 모범 답안, 허용 답안, 원자 단위 채점 기준
- 생성 제공자·모델·배치 ID·프롬프트 버전
- 설계 요약, 근거 요약, 품질 점수
- 선수관계 청사진의 과제 유형, 목표 개념, 선수 개념, 방향성 있는 관계, 필수 추론 단계, 실패 신호
- 교과서 파일명, 페이지 범위, 근거 역할, 인용문과 원문 청크

### 불변 버전

버전 행을 선택하면 버전 메타데이터와 고정 문항 목록을 표시한다.

- 버전, 제목, 설명, 상태, 문항 수, 분포, 내용 해시, 상위 버전, 발행 시각
- 데이터셋 내 ordinal 및 고정된 `question_revision`
- 문항 상세는 작업 세트와 같은 구조를 사용하되, 최신 revision이 아니라 버전에 고정된 revision을 조회한다.
- 고정 revision과 현재 revision이 다르면 이를 명시해 재현 가능성을 보호한다.

## 채점 프로필 감사 화면

프로필별로 다음 내용을 공개한다.

- 버전, 제목, 생성 시각, 내용 해시
- Judge 제공자와 모델 또는 결정론적 채점 여부
- 지표별 한글 이름, 분류, 정의, 평가 대상, 점수 범위, 높은 점수의 의미, 판정 방식
- 선수관계 전용 지표의 상세 루브릭
- 프로필에 저장된 전체 Judge 루브릭 프롬프트
- `질문 및 근거 → 모델 응답 → 결정론적 지표/Judge → 점수·라벨·판정 이유·근거 저장` 처리 흐름
- 해당 프로필을 사용한 실행 수와 최근 실행 링크

## 지표 정의

지표 설명은 화면별 하드코딩을 피하고 `src/domain/score-metrics.ts`의 단일 레지스트리에서 관리한다. 알 수 없는 사용자 정의 지표도 숨기지 않고 “사용자 정의 지표”로 표시하며, 저장된 루브릭 프롬프트가 최종 정의임을 명시한다.

## 조회 구조

- `src/server/datasets/audit.ts`가 작업 세트, 불변 버전, revision, 근거, 생성 provenance를 한 번에 정규화한다.
- 페이지 서버 컴포넌트가 조회 결과를 클라이언트 컴포넌트에 전달한다.
- 새 API나 DB migration은 추가하지 않는다. 기존 불변성 trigger와 저장 데이터를 그대로 사용한다.
- JSON 필드는 예상하지 못한 형태여도 화면 전체를 깨뜨리지 않도록 배열·객체를 안전하게 정규화한다.

## 화면 구조

- 데이터셋 화면은 기존 확정 기능과 분포를 유지한다.
- 그 아래에 작업 세트 감사 목록과 불변 버전 감사 목록을 둔다.
- 선택한 문항은 `<details>` 기반의 중첩 섹션으로 표시해 긴 정보가 기본 화면을 압도하지 않게 한다.
- 채점 프로필은 기존 생성 폼을 유지하고, 각 프로필의 메타데이터·지표 정의·루브릭·실행 이력을 펼쳐 본다.
- 민감한 API 키와 환경변수 값은 노출하지 않는다.

## 검증

- 단위 테스트로 지표 레지스트리와 JSON 정규화를 검증한다.
- 통합 테스트로 불변 버전이 고정 revision을 읽고 작업 세트가 현재 revision을 읽는지 검증한다.
- 컴포넌트 테스트로 연구자에게 필요한 문항·근거·청사진·프로필 설명이 렌더링되는지 검증한다.
- 전체 단위/통합 테스트, 타입 검사, 프로덕션 빌드를 실행한다.
